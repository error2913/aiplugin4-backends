# 后端文档

后端卡片「⚙ 配置」支持的字段类型（在 `backend.json` 的 `config` 里声明）：`text` 文本框、`number` 数字框、`boolean` 开关（保存为 `1`/`0`）、`tristate` 自动/开启/关闭 下拉（保存为空/`1`/`0`）。`{REPO_ROOT}` 模板会展开为仓库根目录。

后端程序不随仓库分发：主仓库只带框架与注册表信息（`backends.json`，含名称/版本/下载源/文件清单），每个后端的源码独立维护在 `shop` 分支（供 release 打包与下载回退）。在 WebUI 或命令行「安装」后，程序才按注册表版本从 GitHub release 独立包下载到 `installed/<名称>/` 运行目录（已 gitignore），下载失败自动回退缓存或远端文件。

## 后端介绍

### stream-output — 流式输出中转

代理 OpenAI 兼容接口，把流式输出按符号/长度切成片段，前端可实时轮询出打字机效果，结束后返回用量统计。

- 默认端口 3010（Python / FastAPI），接口：
  - `POST /start`：body `{url, api_key, body_obj}`（`body_obj` 为 chat.completions 参数），返回任务 `{id}`
  - `GET /poll?id=<id>`：轮询已生成的分块
  - `GET /end?id=<id>`：结束任务，返回片段与 usage
- 依赖：`fastapi`、`openai`、`tiktoken`、`uvicorn`

### image-url-to-base64 — 图片 URL 转 base64

下载图片并转成 base64，自动识别格式（jpg / png / gif / webp），静态 GIF 自动转成 PNG。

- 默认端口 46678（Python / Flask）
- 接口：`POST /image-to-base64`，body `{url}`，返回 `{base64, format}`
- 下载前还原 URL 中的 `&amp;` 等 HTML 实体（QQ 官方 bot 图片 URL 常见）；连接/读取超时 `(10, 30)` 秒；4xx 不重试；上游 4xx / 网络错误 / 自身异常返回不同错误信息（带 `upstream_status`，不回显完整 URL）
- 依赖：`flask`、`Pillow`、`imageio`、`requests`

### usage-chart — token 用量图表

按月/年聚合数据生成图表图片，返回临时图片 URL（约 120 秒后自动清理）。

- 默认端口 3009（Python / FastAPI）
- 接口：`POST /chart`，body `{chart_type, data}`，`chart_type` 支持 `year` / `month`，返回 `{image_url}`（图片在 `/temp_images/<file>.png`）
- 依赖：`fastapi`、`matplotlib`、`python-dateutil`、`uvicorn`

### md-html-render — Markdown / HTML 渲染为图片

把 Markdown 或 HTML 渲染成图片，支持 LaTeX 公式、浅色/深色/渐变主题与宽度/质量参数。

- 默认端口 37632（Node / Express）
- MCP（Streamable HTTP）：`http://127.0.0.1:37632/mcp`，工具 `render_markdown` / `render_html`（返回 PNG base64）
- 依赖：`express`、`puppeteer`、`marked`（需要 Chromium）

### mcp-files-exec — MCP 文件、下载与命令执行（默认开放）

AI 通过 MCP 协议直接读写后端主机文件、下载附件/URL、列目录、删除文件并执行命令。默认允许绝对路径和任意命令；如需要可通过环境变量恢复路径沙箱与危险命令拦截。

- 默认端口 3910（Python / FastMCP），传输 streamable-http；加 `--stdio` 切换为 stdio 传输
- 默认沙箱工作路径为仓库根 `data/mcp-files-exec`（分号可指定多个），数据不在程序目录里，后端更新/卸载不会删除；可在卡片「⚙ 配置」中修改。HTTP 请求携带 `X-Aiplugin4-Session: <会话ID>`（URL 编码）时，相对路径与命令默认工作目录按会话隔离到 `沙箱根/sessions/<清洗后的会话ID>`，无会话（stdio/老客户端）仍落共享沙箱根
- Tools：`read_file`、`list_dir`、`write_file`（支持追加）、`delete_file`、`download_file`、`run_shell`、`export_file`
- 环境变量：`MCP_SANDBOX_ROOTS`（沙箱根目录）、`MCP_ALLOWED_COMMANDS`（命令白名单）、`MCP_MAX_FILE_BYTES` / `MCP_MAX_OUTPUT_BYTES`（读写/输出上限）、`MCP_DEFAULT_TIMEOUT`（命令超时）、`MCP_LOG_FILE`（审计日志）、`MCP_ALLOW_EXTERNAL_PATHS`（允许绝对路径访问沙箱外文件）、`MCP_ALLOW_DANGEROUS_COMMANDS`（关闭危险命令拦截与命令白名单）
- 依赖：`mcp`、`uvicorn`

### ob11-core-bridge — SealDice 双连接冗余 / OB11 指令中转

海豹双连接冗余部署下的 API 中转与核心指令注入通道：海豹**直连协议端的 OB11 正向 WS** 负责实时消息收发；`/core`（及 `/core/ws`）连接的桥只做核心 API 请求 → 协议端的转发与响应回传，以及经 `/plugin` 注入假消息执行核心指令并收集/转发响应。协议端推送给桥的实时事件（message/notice/request/meta）一律丢弃，避免同一条事件双份进入海豹导致重复处理。

- 默认端口 46880（Node，内置 http + ws）
- 端点：`/core`（及 `/core/ws`）接海豹核心正向 WS；协议端由中间件作为 WS 客户端**出站主动连接**（不支持反向 WS），启动即连并带指数退避重连（1s 起、上限 30s）；`/plugin` 接 aiplugin4 插件控制 WS（`core_command` 请求/响应）
- `run_core_command` 由 aiplugin4 插件本地注册为 AI 工具，经 `/plugin` WS 注入核心指令并获取完整结果（多消息、`forward`、`ambiguous`、超时与断线均在结果 JSON 中）；`run_ext_command` 由 aiplugin4 插件前端本地实现，不属于本后端
- 部署要求（1.1.0 破坏性变更）：海豹必须另接一条直连协议端的 OB11 正向 WS（建议排在账号列表首位）作为实时消息入口；桥断线不影响聊天与 AI，仅 `run_core_command` 不可用
- 协议端配置：在卡片「⚙ 配置」填写「协议端 WebSocket 地址」与「协议端 token」（可选），保存后**重启该后端**生效；token 同时以 `access_token` 查询参数与 `Authorization: Bearer` 头发送（环境变量 `AIPLUGIN4_BRIDGE_PROTOCOL_URL` / `AIPLUGIN4_BRIDGE_PROTOCOL_TOKEN`）
- 排障：中间件有核心/协议端/插件连接与断开日志；`/healthz` 返回 `coreConnected` / `protocolConnected` / `pluginConnected` / `droppedProtocolEvents`；协议端未配置/不可达时持续重试并在连上后自动恢复，未连接期间核心发来的 API 请求（如 `get_login_info`）立即收到 `status: failed`，不会静默等待超时
- 依赖：`ws`

> 所有后端统一支持：卡片「⚙ 配置」可改端口、token 与监听 IP；设置 token 后请求需带 `Authorization: Bearer <token>` 或 `X-Token: <token>`，监听 IP 默认 `0.0.0.0`。

## 插件配置导出

WebUI 工具栏的两个复制按钮把已安装后端转成插件可直接粘贴的 JSON；CLI 等价命令 `aibackend plugin-config` / `aibackend mcp-config`。

- `📋 复制后端配置` → 插件「后端 → 后端配置」：`{version:1, backends:{<后端名>:{url, token?}}}`，覆盖 stream-output / image-url-to-base64 / media-fetch / usage-chart / image-host / ob11-core-bridge。
- `📋 复制 MCP 配置` → 插件「MCP → MCP服务器」：标准 `mcpServers`，覆盖 mcp-files-exec / md-html-render / mcp-browser，`url` 为 `/mcp`，后端 token 非空时写 `headers.Authorization`，`platform` 取注册表元数据（md-html-render 默认 `["QQ"]`）。
- 只导出已安装（程序 + 依赖就绪）的后端；访问主机默认 `127.0.0.1`，预览里可改；后端监听具体 IP 时以该 IP 为准。
- MCP 配置粘贴会整体替换「MCP服务器」；手写的其它服务器需要先合并。
- 参与资格与字段由 `backends.json` 的 `pluginConfig` 元数据声明（`backend` / `mcp` 两组）。
- 完整格式与设计见 [插件配置导出方案](插件配置导出方案.md)。

## URL HTML 实体解码（issue #3）

QQ 官方 bot 的图片 URL 来自 JSON/HTML 上下文，`&` 常被转义成 `&amp;`。`image-url-to-base64`（1.0.1）与 `image-host`（1.0.10）在下载前会还原 `&amp;` / `&#38;` / `&#x26;`（只解 ampersand 族，不使用 `html.unescape`，避免破坏 `&notify=1` 这类合法参数）；`image-host` 对重定向 `Location` 也做同样处理。i2b64 同时改为：4xx 不重试、错误区分上游 4xx / 网络错误 / 自身异常（响应带 `upstream_status` 与 `host`，不回显完整 URL）。

> 修复只对更新后的后端副本生效：已安装用户需要点卡片「⬆ 更新」或卸载重装。

## 后端 WebUI 反代（卡片「🌐 WebUI」）

后端在 `backend.json`（以及 main 的 `backends.json` 注册表条目）声明 `webui` 后，已安装且运行中的卡片会显示「🌐 WebUI」按钮：

```json
"webui": { "path": "/", "title": "图床 WebUI", "proxy": true, "inject_token": false }
```

- `path`：后端内 WebUI 入口路径（反代到 `<后端地址><path>`）；`title` 仅用于按钮提示。
- `proxy`：默认 `true`，提供同源反代 `/ui/<名称>/`；设为 `false` 时按钮改为直连后端端口（适用于必须独占根路径、或用了 WebSocket 的复杂页面）。
- `inject_token`：默认 `false`；开启后 launcher 反代会自动给后端请求带上该后端的 `X-Token`，仅用于没有自身登录入口的 WebUI（后端自身鉴权仍优先）。

使用与安全：

- 反代只允许本机、已登记、运行中的后端，上游固定 `127.0.0.1:<port>`（监听 IP 为 `0.0.0.0` 时），不接受 URL 参数，无 SSRF；未安装 / 未运行 / 未声明分别返回 404 / 503 / 403 HTML。
- 需要先在 launcher 登录（token）；`/ui/*` 页面导航使用仅作用于 `/ui` 的 HttpOnly cookie（由 token 派生，换 token 自动失效），launcher 自身 `/api/*` 仍只认 header token。
- 因此后端可以只监听 `127.0.0.1`：插件同机时仍用 `http://127.0.0.1:<port>` 调 API，WebUI 经 launcher 打开，**无需把后端端口再开放到公网**。若 launcher 对公网暴露，请配合 HTTPS 反代并换强 token。
- 后端 WebUI 前端需使用相对 URL（或基于 `document.baseURI` 解析），以便同时适配直连与 `/ui/<名称>/` 子路径；反代会传 `X-Forwarded-Prefix` 供后端自行拼前缀。
- 暂不支持 WebSocket 与 chunked 请求体；大文件上传请用带 `Content-Length` 的 multipart。

## MCP 文件与命令后端（mcp-files-exec）

给 AI 提供 MCP 工具：读写文件、列目录、删除文件、执行受限命令。默认 `streamable-http` 传输（端口 3910），也可 `--stdio` 本地模式（供 MCP 客户端直接拉起）。

工具：`read_file` / `list_dir` / `write_file` / `delete_file` / `download_file` / `run_shell` / `export_file`。默认直接接受后端主机上的绝对路径；相对路径在有会话（`X-Aiplugin4-Session` 请求头）时相对该会话工作区解析，无会话时相对第一个沙箱根目录解析。

运行模式：

- 直接路径：默认 `MCP_ALLOW_EXTERNAL_PATHS=1`，AI 可把消息中的 `path` / `local_path` 直接传给所有文件工具；这要求该路径存在于 MCP 后端所在主机
- 跨主机附件：使用 `download_file(url, path)` 把消息中的 URL 下载到后端任意目标路径，再调用 `read_file` 或 `run_shell` 处理；下载工具不限制 URL 类型
- 命令执行：默认 `MCP_ALLOW_DANGEROUS_COMMANDS=1`，不启用危险命令拦截和 `MCP_ALLOWED_COMMANDS` 白名单；设为 `0` 才恢复限制
- 执行控制：仍保留超时强杀进程树和输出截断，避免单次调用无限等待；可用配置调整
- 审计日志：每次调用记录到 `logs/mcp-files-exec.log`
- 文件导出：`export_file` 返回短时下载地址，供 QQ/Milky 等协议端代取文件

环境变量：

| 变量 | 说明 | 默认 |
| --- | --- | --- |
| `MCP_SANDBOX_ROOTS` | 允许的沙箱根目录，`os.pathsep` 分隔 | `data/mcp-files-exec`（仓库根下；WebUI「⚙ 配置」可改，直接以 `--stdio` 拉起时回退进程当前目录） |
| `MCP_ALLOWED_COMMANDS` | 命令白名单前缀，`os.pathsep` 分隔 | 未启用（危险规则拦截） |
| `MCP_MAX_FILE_BYTES` | 单文件读写上限 | 1048576 |
| `MCP_MAX_OUTPUT_BYTES` | 命令输出上限 | 1048576 |
| `MCP_DEFAULT_TIMEOUT` | 命令默认超时（秒） | 30 |
| `MCP_ALLOW_EXTERNAL_PATHS` | 允许绝对路径访问沙箱外文件 | `1`（默认开放；设为 `0` 恢复沙箱） |
| `MCP_ALLOW_DANGEROUS_COMMANDS` | 关闭危险命令拦截与命令白名单 | `1`（默认开放；设为 `0` 恢复拦截） |
| `MCP_LOG_FILE` | 审计日志路径 | `logs/mcp-files-exec.log`（仓库根下；WebUI「⚙ 配置」可改） |
| `MCP_MAX_EXPORT_BYTES` | `export_file` 单文件导出上限 | 同 `MCP_MAX_FILE_BYTES` |
| `MCP_EXPORT_TTL_SECONDS` | 导出下载令牌有效期（秒） | 300 |
| `MCP_PUBLIC_URL` | 文件下载地址公网前缀（反向代理时填写） | 空（返回相对路径） |
| `MCP_MAX_DOWNLOAD_BYTES` | `download_file` 下载上限（字节，0=不限制） | `0` |
| `MCP_DOWNLOAD_TIMEOUT` | `download_file` 超时（秒） | `120` |

### image-host — 私人图床 + 图库

按 URL 抓取 QQ 等**短时效图片直链**并落库，对外提供稳定地址，解决「原链接过期后模型 / 协议端取不到图」；同时它也是一个可管理的私人图库（来源、重命名、标签、回收站）。

- 默认端口 46680（Python / Flask）；数据目录 `data/image-host/`（SQLite + `shards/` 原图 + `thumbs/` 缩略图）
- 公开读（无需 token）：`GET /i/<id>` 原图、`GET /i/<id>/b64` base64、`GET /t/<id>` 缩略图、`GET /api/health`
- 鉴权（`Authorization: Bearer <token>` 或 `X-Token`）：`POST /api/upload`（URL 抓取 / base64 / multipart）、`POST /api/release`、`POST /api/exists`、`POST /api/batch`、`GET /api/changes`、`GET /api/list`、`GET /api/tags`、`PATCH|DELETE /api/image/<id>`
- WebUI：`GET /`，**开关** `AIPLUGIN4_IMAGE_HOST_WEBUI`（`on`/`off`）+ 密码 `AIPLUGIN4_IMAGE_HOST_PASSWORD`（默认 `123456`）；三视图（图库 / 回收站 / 标签），支持多选·拖拽·粘贴·URL 导入上传、批量打标签 / 删除 / 存图库、`dry_run` 预演；每张图有 **「详情」** 弹层（完整 sha256 ID、格式/MIME、字节数、缩略图大小、创建/最后访问时间、全部标签、全部来源记录含会话与原始链接、复制链接）；卡片「🌐 WebUI」可经 launcher `/ui/image-host/` 反代打开（1.0.6 起前端统一用相对 URL，直连端口与反代均可）
- MCP：`POST /mcp`，工具 `image_search` / `image_rename` / `image_tag` / `image_keep` / `image_tags`
- 关键设计：id = `sha256(字节)` 内容寻址（天然去重）；`ref` 表做引用计数（同一张图被多群转发只存一份字节）；`origin=manual`（手动上传 / 收进图库）**永不自动清理**；容量按 `CAP` + LRU 淘汰，压力下先清回收站
- **去重后的清理语义**：释放某个 `ref` 只减引用，字节保留到引用为 0（仍不立即删，等容量淘汰/回收站过期）；去重命中且本次来源是 manual 时会把 blob 提升为 `manual`（此前"插件先抓、用户后再手动上传同一张"的图仍会被容量淘汰，1.0.8 修复）；WebUI 删除是整张图（所有 ref 一起软删，`change_log` 会为每条 ref 记 `delete_ref`），彻底删除时 ref 随 blob 级联删除
- 回归测试：`python backends/image-host/tests/test_dedupe_cleanup.py`（24 项断言，直接测 Store，无需起服务）
- 依赖：`flask`、`requests`、`pillow`
- **后端卡片「⚙ 配置」可直接改（6 项）**：数据目录、WebUI 开关、WebUI 密码、容量上限、单图上限、回收站保留天数（保存后重启后端生效）
- **接口里的地址一律是相对路径**（`/i/<id>`、`/t/<id>`、`/i/<id>/b64`）：插件自己拼后端地址（`http://127.0.0.1:46680` + 路径）即可；需要公网/域名时在**插件侧**配置前缀，后端不管
- 抓取只做基础 SSRF 防护（私网 IP、逐跳重定向校验），**没有域名白名单**
- 环境变量：

| 变量 | 说明 | 默认 |
| --- | --- | --- |
| `AIPLUGIN4_IMAGE_HOST_DIR` | 数据目录 | `data/image-host` |
| `AIPLUGIN4_IMAGE_HOST_WEBUI` | WebUI 开关（`on`/`off`，重启生效） | `on` |
| `AIPLUGIN4_IMAGE_HOST_PASSWORD` | WebUI 密码 | `123456` |
| `AIPLUGIN4_IMAGE_HOST_CAP_MB` | 总容量（原图 + 缩略图） | `2048` |
| `AIPLUGIN4_IMAGE_HOST_MAX_FILE_MB` | 单文件上限 | `8` |
| `AIPLUGIN4_IMAGE_HOST_TRASH_DAYS` | 回收站保留天数（`0` = 关闭回收站） | `7` |
| `AIPLUGIN4_IMAGE_HOST_CHANGE_KEEP_DAYS` | 变更日志保留天数（不在卡片里，进阶） | `30` |
