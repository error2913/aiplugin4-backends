# 插件配置导出与整合方案

> 状态：**后端侧（aiplugin4-backends）已实施**；插件侧（aiplugin4）未实施，等后续版本。
>
> 目标：在启动器 WebUI 一键导出「插件实际要用的配置」，粘贴进海豹即可导入，替代逐项手填。
>
> 关联：GitHub issue #3（QQ 官方 bot 图片 URL 的 `&amp;` 未被解码）的修复随本方案一起发布。

## 1. 最终形态

```
aiplugin4-backends WebUI                         海豹 → 插件设置 → aiplugin4
┌──────────────────────────────────┐
│ ▶ 启动全部 ■ 停止全部 🔄 重启全部   │
│ 📋 复制后端配置  📋 复制 MCP 配置  👁 预览 │
└──────────────┬───────────────────┘
               │ 复制后端配置                      ┌─────────────────────────────┐
               └──────────────────────────────▶ │ 后端 → 后端配置 [JSON v1]    │
               │ 复制 MCP 配置                     ├─────────────────────────────┤
               └──────────────────────────────▶ │ MCP → MCP服务器 [mcpServers] │
                                                  └─────────────────────────────┘
```

- 两个导出互相独立：后端 JSON 只含 6 个「后端」项目；MCP JSON 只含 3 个 MCP 项目。
- 论坛不是 aiplugin4-backends 的项目，不参与任何导出。
- 导出只含**已安装**（程序 + 依赖就绪）的后端；未安装的不写入，插件侧使用默认值。
- 复制内容含 token（图床 / 核心桥 / MCP 访问 token），不要公开分享。

## 2. 数据契约 A：后端配置

粘贴位置：海豹「后端 → 后端配置」（插件侧尚未实施；格式先冻结）。

```json
{
  "version": 1,
  "backends": {
    "stream-output":       { "url": "http://127.0.0.1:3010" },
    "image-url-to-base64": { "url": "http://127.0.0.1:46678" },
    "image-host":          { "url": "http://127.0.0.1:46680", "token": "…" },
    "media-fetch":         { "url": "http://127.0.0.1:46679" },
    "usage-chart":         { "url": "http://127.0.0.1:3009" },
    "ob11-core-bridge":    { "url": "ws://127.0.0.1:46880/plugin", "token": "…" }
  }
}
```

| 后端名 | 插件运行时字段 | URL | token |
| --- | --- | --- | --- |
| `stream-output` | `STREAM` | `http(s)://host:port` | 不导出 |
| `image-url-to-base64` | `IMAGE_TO_BASE64` | 同上 | 不导出 |
| `image-host` | `IMAGE_HOST` / `IMAGE_HOST_TOKEN` | 同上，空 = 禁用 | 该后端的访问 token |
| `media-fetch` | `MEDIA_FETCH` | 同上，空 = 禁用 | 不导出 |
| `usage-chart` | `USAGE_CHART` | 同上 | 不导出 |
| `ob11-core-bridge` | `CORE_BRIDGE_WS_URL` / `CORE_BRIDGE_TOKEN` | `ws(s)://host:port/plugin` | 插件控制 WS token |

约定：

- 键 = 后端名（与 `backends.json` 一致）。
- 缺省 = 插件出厂默认；显式 `"url": ""` = 禁用（仅图床、媒体转 base64 支持）。
- `version` 固定 `1`；未知后端名由插件侧 warning + 忽略；结构/类型/协议错误整份拒绝。
- 未安装的后端不写入；插件侧缺省即默认值。

## 3. 数据契约 B：MCP 配置

粘贴位置：海豹「MCP → MCP服务器」（需先开启「是否启用MCP」）。格式与 `aiplugin4-config` 生成器的「MCP」页一致，**没有 `version`**：

```json
{
  "mcpServers": {
    "mcp-files-exec": {
      "type": "http",
      "url": "http://127.0.0.1:3910/mcp",
      "headers": { "Authorization": "Bearer <该后端的访问 token>" }
    },
    "md-html-render": {
      "type": "http",
      "url": "http://127.0.0.1:37632/mcp",
      "platform": ["QQ"]
    },
    "mcp-browser": {
      "type": "http",
      "url": "http://127.0.0.1:8921/mcp"
    }
  }
}
```

规则：

- 只含已安装且声明了 MCP 元数据的后端；本期 3 个：`mcp-files-exec`、`md-html-render`、`mcp-browser`。
- `type` 固定 `http`；`url` = `http://<host>:<有效端口>/mcp`。
- 后端 token 非空时写 `headers.Authorization = Bearer <token>`；空则整个 `headers` 省略。
- `platform` 来自注册表元数据；`md-html-render` 默认 `["QQ"]`（与生成器默认示例一致）。
- 不写 `token` 简写、不写 `enabled`、不写 `version`。
- **粘贴是整份替换**：会覆盖手写的其它 MCP 服务器。需要保留时先合并，不要整段粘贴。
- 一个 MCP 后端都没安装时不复制空配置（避免误清空）。

## 4. 启动器侧实现（本仓库）

### 4.1 元数据（`backends.json`）

每个后端用一个可选 `pluginConfig` 字段声明参与方式；未声明者自动不参与：

```json
// stream-output / image-url-to-base64 / media-fetch / usage-chart
"pluginConfig": { "backend": { "scheme": "http" } }

// image-host
"pluginConfig": { "backend": { "scheme": "http", "tokenFrom": "backend",
                               "tokenRequired": true } }

// ob11-core-bridge
"pluginConfig": { "backend": { "scheme": "ws", "path": "/plugin",
                               "tokenFrom": "options.plugin_token" } }

// mcp-files-exec
"pluginConfig": { "mcp": { "path": "/mcp" } }

// md-html-render
"pluginConfig": { "mcp": { "path": "/mcp", "platform": ["QQ"] } }

// mcp-browser
"pluginConfig": { "mcp": { "path": "/mcp" } }
```

- `tokenFrom: "backend"` 取 `.runtime.json` 的 `config.<name>.token`；
- `tokenFrom: "options.<key>"` 取该后端自定义配置项（核心桥为 `plugin_token`）；
- `tokenRequired: true` 在 token 为空时给出警告（图床写接口会 401）；
- `mcp` 分组默认使用后端 token 作为 `headers.Authorization`。

### 4.2 生成规则

- 端口取 `backend_config()["port"]`（含 `.runtime.json` 覆盖值）。
- 主机：后端配置的 host 是具体 IP → 用该 IP；`0.0.0.0` / `::` / 空 → 用请求的 host（默认 `127.0.0.1`）。
- 地址永远不出现 `0.0.0.0`。
- 输出顺序固定按注册表顺序，保证同样安装状态生成同样文本。
- 后端 JSON 紧凑输出（`json.dumps(..., separators=(",", ":"))`），不写时间戳/来源等元数据。
- 排除原因：`未安装`（程序 + 依赖未就绪）。

### 4.3 API / CLI

| 用途 | API | CLI |
| --- | --- | --- |
| 后端配置 | `GET /api/plugin-config?host=127.0.0.1` | `aibackend plugin-config [--host H] [--pretty]` |
| MCP 配置 | `GET /api/mcp-config?host=127.0.0.1` | `aibackend mcp-config [--host H] [--pretty]` |

响应：

```json
{
  "ok": true,
  "host": "127.0.0.1",
  "text": "{...}",
  "config": { "...": {} },
  "included": [{ "name": "image-host", "url": "http://127.0.0.1:46680", "token": true }],
  "excluded": [{ "name": "stream-output", "reason": "未安装" }],
  "warnings": ["image-host 未设置访问 token：插件上传/取图会返回 401"]
}
```

### 4.4 WebUI 交互

- 工具栏「📋 复制后端配置」：直接生成并写剪贴板；toast 指明粘贴位置。
- 工具栏「📋 复制 MCP 配置」：同上；toast 额外提示「粘贴会整体替换 MCP服务器」。
- 「👁 预览」：弹窗可在「后端配置 / MCP 配置」间切换，显示格式化 JSON、纳入/排除项、警告、访问主机输入；支持复制/下载。
- 剪贴板：`navigator.clipboard.writeText` → 失败降级 `textarea + execCommand` → 仍失败则打开预览并全选。局域网 `http://` 不是安全上下文，必须有降级。
- 访问主机存 localStorage（默认 `127.0.0.1`），预览里可改成局域网 IP/域名。
- 未安装任何 MCP 后端时，「复制 MCP 配置」提示且不复制空配置。

## 5. 插件侧实现（未实施，后续）

> 以下是已冻结的设计，插件侧落地时照此实现。

- 新增配置键 **`后端配置`**（String，JSON v1，分组「后端」），替换原来的 8 个后端键：
  - 流式输出、图片转base64、图床、图床Token、媒体转base64、用量图表、核心桥WS地址、核心桥Token；
  - 旧键不再注册（变 deprecated、界面隐藏），保留在 `config.json` 里。
- 新增「论坛」页签：`论坛地址` / `论坛API Token` / `论坛签名密钥`（键名不变，只是换分组；值自动保留）；`tool_forum.ts` 改读 `Config.forum`。
- 解析/校验：`version` 必须为 1；未知后端名 warning + 忽略；缺省项合并出厂默认；显式空 URL 仅对图床/媒体转 base64 合法；结构/类型/协议错误整份拒绝（一次报全，路径 `$.backends.image-host.url`）。
- 兼容：文本为默认值 / 非法时，只读旧 8 键兜底（不写回），日志提示用启动器重新复制；旧键仍留在 `config.json`。文本为空时按出厂默认（用户主动清空不复活旧值）。
- 生效：`Config.backend` 60s TTL，保存后最迟 60 秒生效；已建立的核心桥 WS 连接需重连或重载 JS。
- 描述统一：新增 `BACKEND_CONFIG_HINT`，与 `GENERATOR_CONFIG_HINT` 同句式，不内嵌 JSON 示例。
- MCP 侧零代码改动（现有标准 `mcpServers` 解析已支持）。

## 6. URL HTML 实体解码修复（issue #3，本仓库已实施）

现象：QQ 官方 bot 图片 URL 形如 `?appid=…&amp;fileid=…&amp;rkey=…&amp;spec=0`，后端把 `amp;fileid` 当参数名，上游 400。

修复：

- **i2b64**（`backends/image-url-to-base64/urltobase64.py`，1.0.1）：
  - 解码 `&amp;` / `&#38;` / `&#x26;`（最多 3 轮，只解 ampersand 族，**不用 `html.unescape`**，避免把合法 `&notify=1` 解成 `¬ify=1`）；
  - 加请求超时；4xx 不重试；错误区分上游 4xx / 网络错误 / 后端自身异常，响应带 `upstream_status` 与 `host`（不回显完整 URL）。
- **image-host**（`backends/image-host/fetch.py`，1.0.10）：
  - `safe_fetch()` 入口与重定向 `Location` 都做同样解码；SSRF/分类逻辑不变。
- **插件侧**（后续）：
  - `Image.createUrlImage`、`Image.get`（revive）、消息图片段解析处解码，治愈旧存量图片；
  - `isPermanentUrlError` 兼容 `upstream_status: 4xx`；
  - 这样 i2b64 / 图床 / 模型 / `checkImageUrl` 全部拿到正确 URL。

注意：修复只对**已更新**的后端副本生效。已安装用户需要点卡片「⬆ 更新」（注册表版本提升后出现）或卸载重装。

## 8. 测试与验收

- 启动器：`python -m unittest discover -s tests -v`
  - 后端导出：默认主机、0.0.0.0 归一化、未安装排除、token 取舍、核心桥 `/plugin`、紧凑序列化。
  - MCP 导出：只含已安装 MCP、`type/url/headers/platform`、空 token 省略 headers、空集合。
- CLI 冒烟：`python launcher.py plugin-config` / `mcp-config` 输出合法 JSON。
- 后端：
  - i2b64 解码 + 查询串还原 + 4xx 不重试；
  - image-host 解码 + 重定向 Location。
- 手工验收：
  - 安装 2 个后端（其中一个设 token）→ 复制后端配置 → JSON 正确；
  - 安装 2 个 MCP 后端 → 复制 MCP 配置 → 结构和生成器示例一致；
  - 带 `&amp;` 的图片 URL 走 i2b64 / 图床均成功。

## 9. 非目标

- 不把 MCP / 论坛并入后端 JSON；
- 不导出 `image-host` 的 `/mcp`（以后加元数据即可）；
- 不做合并导入（启动器读不到海豹当前配置）；
- 不做自动写入/同步；
- 不在预览里做完整 MCP 编辑器（`platform` 固定按注册表，粘贴后可手改）。
